# AGENTS.md

Контекст для любых AI-ассистентов (Claude Code, Codex, Cursor и др.) и новых участников команды.
Файл короткий намеренно: здесь карта и правила, детали лежат в `docs/`.

## Проект одной фразой

Хакатон ЛЦТ 2026, задача №1 (ДПиИР Москвы + АНО «ФЦ БАС»): **веб-платформа экспресс-оценки роботизации объекта**.
Каталог роботов → объяснимый подбор под параметры объекта → количество и экономика (как сейчас / покупка / RaaS) →
2D-имитация, которая подтверждает расчёт → отчёт PDF/Excel. Дедлайн сдачи — **29.09.2026, 23:59 МСК**.

## Текущая фаза

Формируем продуктовое видение и принимаем ключевые решения (стек, основа кода, глубина симуляции).
В репозитории есть прототип v0 (Vite/React + FastAPI/SimPy). Он **не является утверждённым направлением**: решение
«сохраняем / переписываем» записывается в `docs/DECISIONS.md`. Актуальное состояние — `docs/STATUS.md`.

## Что читать и в каком порядке

1. `docs/STATUS.md` — где мы сейчас, что дальше, риски (читать всегда).
2. `docs/DECISIONS.md` — принятые решения и открытые вопросы (читать всегда).
3. `docs/CASE_BRIEF.md` — выжимка ТЗ, дополнений и Q&A: требования, критерии, сроки.
4. По задаче: `docs/PRODUCT.md` (видение, фичи, демо), `docs/DATA.md` (датасеты и ловушки),
   `docs/MARKET.md` (рынок, конкуренты, бенчмарки цен), `docs/CONTRACTS.md` (доменная модель и API).
5. Первоисточники — только когда нужна точная формулировка: `case/`.

## Правила работы

- **ТЗ — источник истины.** Если идея противоречит `docs/CASE_BRIEF.md`, побеждает ТЗ. Сомнение → свериться с `case/task/`.
- **Никаких недокументированных коэффициентов** (ТЗ 3.5.1). Каждое число в расчётах имеет источник: датасет, ТЗ,
  открытый источник со ссылкой и датой или явное допущение команды с обоснованием. Магические константы в коде
  не допускаются: норматив живёт в реестре допущений, а не в строке кода.
- **LLM не считает.** LLM допустим для импорта, извлечения, объяснений и текста отчёта. Подбор, количество, экономика,
  симуляция — детерминированный код с тестами.
- **Симуляция влияет на расчёт.** Её результат обязан участвовать в логике (например, в итоговом количестве роботов
  или в резерве), жюри проверит это по коду. Декоративная анимация не засчитывается.
- **Интерфейс только на русском**, у полей единицы, подсказки, примеры; работает от 1366×768.
- Код, идентификаторы и коммиты — на английском. Документация и UI — на русском.
- Никаких реальных ПДн и секретов в репозитории. `case/chat/` и `template/` не коммитить.
- Внешние источники не должны быть точкой отказа демо: всё нужное для демо лежит в репозитории или БД.
- Документацию сторонних библиотек сверять через Context7, а не по памяти.

## Как вести контекст

| Что произошло | Куда записать |
|---|---|
| Приняли решение (стек, формула, граница MVP) | `docs/DECISIONS.md`: новая запись D-NNN, коротко «решение / почему / альтернативы» |
| Появился открытый вопрос | `docs/DECISIONS.md`, раздел «Открытые вопросы» (Q-NNN) |
| Закончили заметный кусок работы | `docs/STATUS.md`: обновить «сделано / дальше / риски», держать файл коротким |
| Поменялась модель данных или API | `docs/CONTRACTS.md` |
| Узнали новое о данных или ловушку | `docs/DATA.md` |
| Новое разъяснение организаторов | `docs/CASE_BRIEF.md` (со ссылкой на источник) |

Держи файлы сфокусированными: `STATUS.md` — до ~80 строк, историю не копить (она в git).
Не дублируй содержимое между файлами — ставь ссылку.

## Запуск прототипа v0

```bash
# backend (Python 3.11+)
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000   # Swagger: http://localhost:8000/docs
.venv/bin/pytest -q                                   # 14 тестов

# frontend (из корня)
npm install && npm run dev                            # http://localhost:5173, /api → :8000

docker compose up                                     # оба сервиса
```
