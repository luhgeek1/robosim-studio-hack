# Лендинг, демо и вход в аккаунт

Актуально с 21.10.2026, D-057. Временная гостевая сессия даёт доступ к пробным проектам,
но не считается полноценным аккаунтом при выборе главного экрана.

| Действие | Без аккаунта, включая гостевой JWT | После входа в аккаунт |
|---|---|---|
| Логотип или `/` | Лендинг | Проекты; для admin/vendor — кабинет роли |
| `/app` | `/demo` | Домашний экран роли |
| `/demo` | Гостевой вход в работу | `/projects` |
| `/demo?new=1` | Гостевое создание | `/projects?new=1`, создание в текущей рабочей области |
| `/demo/:demoKey` | Открытие примера | Явное открытие примера в собственной рабочей области |
| Выход | — | Завершить сессию и открыть `/demo` |

Переход на лендинг не завершает гостевую сессию и не удаляет пробные проекты.
Лендинг предлагает отдельно войти через `/login` или попробовать платформу через `/demo`.
До окончания восстановления сессии роутер показывает ожидание, чтобы не выбрать неправильный экран.

## Возврат после входа и регистрации

Одинаковое правило применяется к credentials и кнопкам OAuth:

1. Обычный вход из `/demo` или `/demo/:demoKey` ведёт в домашний экран роли.
2. Если человек намеревался создать объект (`/demo?new=1`), открывается создание реального проекта.
3. «Сохранить в аккаунт» из уже открытого `/projects/:id` возвращает в этот проект.
   Гостевые проекты переносятся в аккаунт существующим серверным механизмом.
4. Приглашение, настройки аккаунта и другие разрешённые внутренние адреса сохраняются.
   Принятие приглашения по-прежнему требует отдельного действия на его странице.
5. Внешние адреса, обратные слеши и управляющие символы не становятся адресами возврата.
   Возврат к прежнему проекту через состояние роутера учитывает владельца или явное сохранение гостя.

Выбранная организация не сбрасывается переходом по логотипу. Доступ к проектам и организациям
продолжает проверять сервер. После входа «Проекты» показывают текущую рабочую область и кнопку
«Новый проект»; гостевая плашка не используется для обычного аккаунта.

## Где поддерживать правило

- `frontend/src/entities/session/home.ts` — главная по роли и вход в рабочее пространство.
- `frontend/src/features/auth/links.ts` — безопасный адрес возврата и преобразование гостевого намерения.
- `frontend/src/app/guards.tsx` — ожидание сессии, лендинг и вход в демо.
- `LoginPage` и `WorkspaceMenu` — вход и выход; содержимое экрана создания проекта не меняется.

Проверка: `cd frontend && npm run check`; отдельный запуск — `npm run test:routing`.
Шесть тестов покрывают роли, гостя, сохранение проекта/приглашения, создание и небезопасные адреса.
Браузерная проверка на локальном стенде: вход → проекты, выход → демо, логотип → лендинг,
`/demo?new=1` → создание после входа, сохранение гостевого проекта → тот же проект в аккаунте.
