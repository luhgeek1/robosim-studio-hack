# Файлы для проверки импорта

В проекте откройте «Объект» → «Загрузить файл». Выберите файл для соответствующего типа объекта.
Ссылки на основные примеры есть и в самом окне загрузки.

Это учебные данные для проверки интерфейса, а не обследование реального объекта.
Исходные значения полных примеров получены 20.10.2026 через локальный `export.json` демо-склада
и демо-больницы: справочники `backend/app/seeds/data/object_types/`, датасет организатора
`case/dataset/Датасеты_хакатон.xlsx` и явно обозначенные в проекте допущения команды.
Ошибки внесены намеренно. Любая ручная замена ниже — только упражнение, не рекомендация для реального объекта.

| Файл | Что появится | Как проверить исправление |
|---|---|---|
| `warehouse-repairs.json` | 4 ошибочные строки, 3 предложения; высота 10 000 мм показана как 10 м | Нажать «Применить предложения (3)». Для WMS заменить «возможно» на «Да» или «Нет», нажать «Проверить изменения», скачать исправленный JSON и применить |
| `warehouse-duplicates.json` | Две площади, −3 комплектовщика, 2,5 этажа, неизвестное поле | Исключить вторую площадь; поставить 80 комплектовщиков и 2 этажа; неизвестное поле сопоставить с площадью уборки; зону роботизации уменьшить до 10 000 м². Проверить изменения и применить |
| `hospital-repairs.json` | Опечатка типа учреждения, площадь с единицей, 2,5 лифта; 180 000 мм переведены в 180 м | Применить 2 предложения, указать 4 лифта, повторно проверить и применить |
| `broken-json.json` | Уведомление о восстановлении формата: лишняя запятая перед `}` | Проверить площадь, скачать исправленный JSON и импортировать его повторно |
| `warehouse-clean.json`, `hospital-clean.json` | Чистый экспорт без ошибок строк; возможны замечания к исходным допущениям демо | Импортировать в пустой проект соответствующего типа, проверить параметры |

Прежде чем нажать «Применить», проект не меняется. Редактировать можно значение, единицу и сопоставление
каждой строки; ненужную строку можно исключить. После правок нужна повторная проверка.
Кнопка перезаписи ручных значений также пересчитывает предпросмотр. Ошибки связей между параметрами
проверяются ещё раз на сервере при применении, с учётом актуальных данных проекта.

Исправленный файл скачивается отдельным JSON: исходный файл на диске сохраняется.
Переносятся параметры объекта. Сценарии, расчёты и планировка не восстанавливаются из JSON-снимка.
Неоднозначные числа, неизвестные значения и противоречащие единицы требуют ручного решения;
система не угадывает значения, не берёт первое число диапазона и не ограничивает измерение типичной границей.

Повреждённый JSON, который нельзя восстановить удалением лишних запятых, покажет строку и столбец ошибки.
Повреждённый Excel нужно заново сохранить в XLSX; бинарный документ восстановить в этом окне нельзя.

Проверки: `backend/tests/integration/test_import_review_api.py`,
`backend/tests/unit/test_import_values.py`, `backend/tests/unit/test_importers.py`;
браузерный сценарий — `frontend/e2e/import-review.spec.ts`.
