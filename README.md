# РобоМера

Веб-платформа для быстрой оценки роботизации объекта. Задача 1 ЛЦТ 2026 от ДПиИР Москвы и АНО ФЦ БАС.

Пользователь заводит объект (склад, больницу или аэропорт) и за несколько минут получает ответ: каких роботов брать, сколько их нужно, сколько это стоит и за сколько окупится. Каждое число можно раскрыть и посмотреть откуда оно взялось. Количество роботов проверяется имитацией на планировке объекта и результат имитации попадает в расчёт.

## Как запустить

Нужен только Docker с Docker Compose (Docker Desktop на Mac и Windows или docker engine на Linux). Больше ничего ставить не надо, всё собирается в контейнерах.

```
git clone https://github.com/luhgeek1/robosim-studio-hack.git
cd robosim-studio-hack
docker compose up -d --build
```

Первая сборка занимает несколько минут. Когда всё поднимется:

- интерфейс http://localhost:3000
- документация API http://localhost:8000/api/docs

База, миграции, справочники, каталог роботов и демо-учётки создаются сами при первом старте, ничего руками делать не нужно.

Остановить

```
docker compose down
```

Стереть данные и начать с нуля

```
docker compose down -v
```

Если порты 3000, 8000, 5432 или 6379 заняты, освободите их или поменяйте левую часть в ports в файле docker-compose.yml.

## Что посмотреть за 5 минут

1. Войти как пользователь и создать проект из демо-объекта «Склад 20 000 м², 180 сотрудников». Это данные организатора.
2. Шаг Подбор показывает кандидатов по каждому процессу с причинами почему подходит или нет. Кнопка «Сценарий из рекомендации» собирает сценарий, считает экономику и сразу проверяет число роботов имитацией.
3. Шаг Сценарии: откуда взялось число роботов, по формуле и по имитации, можно выбрать что брать в расчёт.
4. Шаг Сравнение: как сейчас, покупка, RaaS, лизинг.
5. Шаг Имитация: смена на карте склада в 2D и 3D, заторы, зарядка, стресс-тесты (+20 % объёма, отказ робота).
6. Шаг Отчёт: PDF и Excel.

Второй демо-склад «Фулфилмент 24/7» это тот же склад организатора в три смены. На нём окупаются сразу три типа роботов (паллетные AMR, товар к человеку и уборка) и видно как несколько типов работают на одной карте. Параметры которые мы поменяли помечены как допущения команды.

Для больницы и аэропорта есть свои демо-объекты из датасета, там тоже строится планировка и работает имитация.

## Что умеет

- Каталог роботов из таблицы организатора с группами характеристик, поиском, фильтрами и сравнением. У каждой характеристики источник и дата, пустые поля видны.
- Подбор по процессам объекта. Жёсткие ограничения (проходы, грузоподъёмность, потолки, температура) отсекают, остальное ранжируется по весам которые пользователь может поменять. У каждого решения видны причины.
- Количество роботов по времени цикла с резервом, потом проверка имитацией. Имитация перебирает размер парка и берёт минимальный, при котором все прогоны пиковых часов держат целевой срок.
- Экономика: CAPEX, OPEX, эффект, окупаемость простая и дисконтированная, NPV, IRR, TCO. Покупка, RaaS и лизинг. Чувствительность и Монте-Карло.
- Планировка генерируется из параметров объекта, маршруты с неё идут в расчёт цикла.
- Отчёт PDF и Excel с допущениями и источниками.
- Админка: каталог, нормативы с версиями, справочники, импорт каталога из файла, пользователи.
- Кабинет производителя: свои карточки, заявки на правки через модерацию, статистика как продукты проходят подбор, ответы на запросы КП.
- Запрос КП из сценария: производитель отвечает ценой и сроком, цену можно подставить в расчёт одной кнопкой.
- Организации с общими проектами и приглашениями.

## Как считаем

Коротко про методику в docs/METHOD.md. Там подбор, количество, экономика, имитация и откуда берутся числа.

Главный принцип: в коде нет чисел без источника. Каждый норматив лежит в реестре допущений с источником или обоснованием, его видно в интерфейсе и в отчёте, администратор может его поменять и выпустить новую версию. Старые расчёты при этом помечаются устаревшими.

## Устройство

- backend FastAPI, PostgreSQL, Alembic, Redis и arq для фоновых задач, SimPy для имитации
- frontend React 19, Vite, TanStack Query, three.js для 3D
- docs/api OpenAPI контракт, по нему проверяется каждый ответ API в тестах
- case/dataset датасеты организатора, бэкенд читает их при первом старте
- research источники для характеристик роботов и сценариев ФЦ БАС

Тесты бэкенда (больше 360) идут на настоящих Postgres и Redis. Расчёт сценария занимает десятки миллисекунд, имитация смены меньше секунды.
