# Продукт: видение и план максимум

> Версия 2 (22.09.2026): решения D-003…D-012 приняты, план максимум утверждён (D-009). Здесь — что делаем и почему.
> Контракт API — `docs/api/`, модель — `docs/CONTRACTS.md`, стандарт кода — `docs/ENGINEERING.md`.

## Позиционирование

**Независимая предынвестиционная оценка роботизации объекта — за 15 минут вместо месяца работы консультантов.**

Не каталог и не калькулятор, а «второе мнение» до того, как компания потратит десятки миллионов. Проблема из самой постановки:
«вендоры дают оценки в свою пользу, независимого инструмента нет». Наш ответ — каждое число проверяемо: у него есть формула,
источник и подтверждение симуляцией.

| Кто | Что получает |
|---|---|
| Предприятие (директор, операционный директор, финансист) | Ответ «стоит ли, что, сколько, когда окупится и где риски» + документ для инвесткомитета + список того, что замерить при обследовании |
| ФЦ БАС | Их «Сценарии внедрения» (16 статичных PDF, `research/fcbas_scenarios/`) становятся интерактивными: пересчёт под объект, подбор вендоров из каталога, проверка симуляцией; данные о спросе; воронка пилотов |
| Вендоры | Квалифицированные запросы с параметрами объекта вместо холодных лидов |

**Подача для заказчика:** тот же язык и та же методика, что в их сценариях (1 робот = 1 линия отгрузки = 3 человека
в 3 смены; 4,4 млн ₽ против 9,4 млн за 3 года), но под конкретный объект и с проверкой достижимости (ТЗ 2.1.4).

## Центральная идея: «паспорт против физики»

Паспортная производительность из материалов организатора — «80–100 паллет/ч на AMR». Наивная формула по ней даёт
2–3 робота на весь склад; реальные внедрения из того же каталога — 48 роботов у «Восток-Сервиса» и 67 FMR в РЦ X5
(масштабы объектов различаются — в питче говорим «на объектах такого класса», не «на таком же»). Разница — в геометрии:
дорога, повороты, подъём груза, зарядка, ожидание в узком проходе.

Платформа считает производительность **из времени цикла на планировке конкретного объекта**, а дискретно-событийная
симуляция на графе маршрутов **проверяет и уточняет** количество роботов и резерв. Уточнённое `N` идёт в экономику
(`CountResult.source = simulated`, видно в трассе). Это закрывает три требования сразу: симуляция участвует в расчёте
(Q&A: проверят по коду), обоснованность расчётов, независимость от вендорских цифр.

## Что изменилось после повторного анализа (Fable, 22.09)

1. **Роботизируем процессы, а не «склад целиком».** В демо-складе 77% ФОТ — отбор (156 млн/год), паллеты — 47 млн.
   Прототип v0 моделировал только паллеты. Сценарий теперь — портфель `процесс → продукт → N`
   (`ScenarioItem[]`): паллетные потоки на транспортных AMR/FMR, отбор — на goods-to-person (Ronavi M, SmartCube) или
   pick-by-light, уборка — площадью. Экономика суммируется по процессам, симуляция моделирует транспорт и goods-to-person
   (станции отбора как ресурсы). Так каталожная иерархия ТЗ (процесс → тип → продукт) становится реальной, а не декоративной.
2. **Диагностика узкого места** (`SimulationSummary.bottleneck`): «добавление роботов не поможет — станции отбора
   загружены на 96%». Это практическая ценность, которой нет у калькуляторов.
3. **«Что уточнить при обследовании»** (`survey-priorities`): чувствительность × происхождение → параметры-допущения
   с наибольшим влиянием и как их замерить. Прямой ответ на ТЗ 3.7.5 и мост к пилоту с ФЦ БАС.
4. **Перебор флота** (`fleet-sweep`): кривая N → SLA / загрузка / окупаемость — одним графиком объясняет, почему 12, а не 10 и не 14.
5. **Калибровка по методике ФЦ БАС** как автотест: модельный кейс из их PDF воспроизводится движком с расхождением
   в допуске; бейдж «сверено с методикой ФЦ БАС» в UI и отчёте.
6. **Реестр нормативов порождает документацию.** Раздел «Экономическая модель с формулами и источниками» (ТЗ 6.5)
   генерируется из `NormSet` и трассы — документация не расходится с кодом.
7. **Интеграционный слой** сразу: ключи API, `POST /integrations/projects` (создать проект из WMS/1С), описание сценариев
   интеграции в документации (ТЗ 3.8.2–3.8.3, бонус «интеграционные API»).
8. **Честная деградация LLM**: демо у жюри в docker без интернета — все функции ассистента имеют fallback на правила.
9. **Обоснованный ML** (`docs/RESEARCH.md`): суррогатная модель симуляции для мгновенного what-if, LLM-извлечение ТТХ
   и умный импорт, семантический поиск каталога. Не «ML ради ML».

## Пользовательский путь (экраны)

1. **Объект.** Тип, параметры формами по группам (единицы, подсказки, примеры, диапазоны) или Excel по шаблону,
   или умный импорт из текста. Панель доверия: введено / из файла / по умолчанию (источник) / допущение / нет данных.
2. **Процессы и подбор.** «Где деньги»: спрос, пик, текущая стоимость по процессам. Для каждого процесса — типы решений
   и продукты со статусом «подходит / требует проверки / не подходит», причинами, недостающими данными и раскладкой скоринга
   с настраиваемыми весами. Ручное добавление с предупреждением. Сравнение бок о бок по 6 группам ТТХ с бейджами источников.
3. **Планировка.** Сгенерированная 2D-схема (зоны, стеллажи, доки, станции, зарядки, проходы) с простым редактором
   и подложкой-планом. Из неё берутся расстояния для цикла и граф для симуляции.
4. **Сценарии и расчёт.** Состав по процессам, финансирование (свои / кредит / лизинг / RaaS), горизонт, переопределения
   нормативов с причиной. Расчёт: цикл → аналитическое N → симуляция → итоговое N с резервом; CAPEX/OPEX по статьям;
   каждая строка раскрывается в формулу и источники; «Как сейчас / Покупка / RaaS / Лизинг» в одной таблице:
   эффект, окупаемость простая и дисконтированная, NPV, IRR, ROI, TCO, денежный поток. Вердикт по диапазонам + риски.
5. **Имитация.** 2D-плеер: роботы, задачи, заторы, зарядки, отказы; старт / пауза / скорость / выбор сценария /
   пиковый день / отказ робота / +20% объёма. KPI в реальном времени, блок «расчёт против имитации», узкое место,
   кривая перебора флота, тепловая карта.
6. **Риски и обследование.** Торнадо (≥3 параметров), тепловая карта «ФОТ × объём», Монте-Карло P10/P50/P90
   и «вероятность окупиться быстрее 3 лет», список «что замерить при обследовании».
7. **Отчёт.** PDF «предТЭО» с дисклеймером, Excel с живыми формулами, DOCX, PNG/GIF имитации; executive summary
   (LLM или шаблон); опционально RFQ вендорам и применимые меры господдержки.

**Каталог** (гость): иерархия, поиск (в т.ч. семантический), фильтры, сравнение, полнота карточки, бейджи
«Есть в реестре 719», «Протестировано ФЦ БАС», «ТТХ подтверждены». **Демо** (гость): предрассчитанный склад
с ограниченным what-if. **Админка:** CRUD каталога, импорт CSV организатора, очередь обогащения ТТХ с модерацией,
плановое автообновление, версии нормативов, пользователи, аналитика спроса для ФЦ БАС.

**P2 — по мере готовности:** умный импорт из текста и файлов; лизинг и кредит при ставке 14% против льготных;

суррогатная модель; семантический поиск; GIF имитации; 3D-вид на тех же событиях; DES для больницы (лифты) и аэропорта.

## Модель расчёта (контур)

- **Спрос:** суточные объёмы по процессам → часовой профиль (норматив с источником) × пиковый коэффициент.
- **Производительность робота:** `3600 / (2L/v_эфф + t_захвата + t_отдачи [+ t_лифта])` × доступность (цикл «работа / зарядка»,
  простои) × целевая загрузка (70–85%, легенда датасета). `L` — из планировки.
- **Количество:** `N₀ = ⌈пик / производительность⌉` → перебор `N₀−1…N₀+2` симуляцией → минимальное N с SLA ≥ цели
  → резерв по стресс-тесту (норматив 15–20%).
- **База:** ФОТ по группам × 12 × 1,302 + техника + потери; индексация зарплат.
- **Покупка:** CAPEX = цена с НДС × N + зарядные станции + инфраструктура (разметка, Wi-Fi) + ПО + интеграция (WMS/1С) + ПНР +
  обучение + резерв 10%. OPEX = сервис + лицензии + электроэнергия + связь + АКБ (замена раз в 3–5 лет) + персонал
  эксплуатации. Замены по сроку службы внутри горизонта.
- **RaaS:** плата за робота в месяц (бенчмарк — от 100 тыс. ₽) + подключение; сервис и ПО включены; срок и выкуп.
- **Лизинг / кредит:** аннуитет по ставке (ключевая 14% по умолчанию), платежи в денежном потоке.
- **Эффект** = высвобожденный ФОТ + иные измеримые эффекты − доп. OPEX. **Метрики:** окупаемость = CAPEX / эффект;
  ROI = (Σэффект − CAPEX) / CAPEX; NPV, IRR, дисконтированная окупаемость; TCO за горизонт (склад 5, остальные 7 лет).
- Всё — в реестре нормативов с источниками (`docs/DATA.md`, `docs/MARKET.md`, `research/`).

## Демо на 5–7 минут

1. **0:00 Крючок.** «Склад 20 000 м², 180 человек, ФОТ 203 млн в год. Вендор обещает окупаемость за год. Проверим».
2. **0:40 Проект из данных организатора.** Excel → предупреждения валидации → панель доверия.
3. **1:20 Где деньги и подбор.** Отбор 156 млн, паллеты 47 млн. По процессам: подходит / проверить / исключено с причинами.
4. **2:10 Паспорт против физики.** Паспорт — 2 робота, цикл на планировке — 11; имитация в пик: очередь растёт, SLA 91% →
   перебор флота → 12 + резерв. Отказ робота — SLA держится. Узкое место — станции отбора, не роботы.
5. **3:30 Экономика.** Как сейчас / покупка / RaaS / лизинг; окупаемость, NPV; клик по строке — формула и источник;
   бейдж «сверено с методикой ФЦ БАС».
6. **4:30 Риски.** Торнадо: главный драйвер — ставка ФОТ; Монте-Карло: 82% окупиться быстрее 3 лет;
   «что замерить при обследовании».
7. **5:15 Отчёт и админка.** PDF + Excel с формулами; админ меняет цену в каталоге → пересчёт с новой версией и диффом.
8. **6:00 Масштаб.** Аэропорт и больница, новый объект через справочники, интеграции, готовность к пилоту с ФЦ БАС.

Цифры — иллюстрация; реальные даст модель.
