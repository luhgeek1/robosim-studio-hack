# Продукт: предлагаемое видение

> **Статус: ПРЕДЛОЖЕНИЕ, не утверждено.** Составлено 19.09 по ТЗ, Q&A, данным, рынку и разбору прототипа v0.

## Позиционирование

**Независимая предынвестиционная оценка роботизации объекта — за 15 минут вместо месяца работы консультантов.**

Не каталог и не калькулятор, а «второе мнение» до того, как компания потратит десятки миллионов. Проблема из самой постановки:
«вендоры дают оценки в свою пользу, независимого инструмента нет». Наш ответ — каждое число проверяемо: у него есть формула,
источник и подтверждение симуляцией.

**Кому и зачем:**

| Кто | Что получает |
|---|---|
| Предприятие (директор, операционный директор, финансист) | Ответ «стоит ли, что, сколько, когда окупится и где риски» + документ для инвесткомитета |
| ФЦ БАС | Каталог отечественных решений превращается в инструмент внедрения; данные о спросе; воронка пилотов; витрина реестра 719 и «Протестировано ФЦ БАС» |
| Вендоры | Квалифицированные запросы с параметрами объекта вместо холодных лидов |

**Подача для заказчика.** У ФЦ БАС уже есть 16 «Сценариев внедрения» роботов — статичные PDF с экономикой
(`docs/MARKET.md`). Мы делаем их **интерактивную версию**: тот же язык и та же методика, но пересчёт под конкретный объект,
подбор вендоров из каталога и проверка симуляцией.

## Центральная идея: «паспорт против физики»

Паспортная производительность из материалов организатора — «80–100 паллет/ч на AMR». Наивная формула ТЗ по ней даёт
**2–3 робота на весь склад**, а реальные кейсы из того же каталога — **48 роботов Ronavi и 67 FMR** на похожих объектах.
Разница — в геометрии: робот тратит время на дорогу, повороты, подъём груза, зарядку и ожидание в узком проходе.

Платформа считает производительность **из времени цикла на геометрии конкретного объекта**, а дискретно-событийная
симуляция на графе маршрутов **проверяет и уточняет** количество роботов и резерв. Уточнённое количество идёт в экономику.
Это закрывает три требования сразу:
- симуляция участвует в расчёте, а не рисует анимацию (жюри проверит это по коду);
- обоснованность расчётов;
- независимость от вендорских цифр.

## Пользовательский путь

Восемь шагов ТЗ, сгруппированные в 5 экранов проекта + каталог + админка.

1. **Объект.** Тип (склад / аэропорт / больница / другое). Параметры формами по группам или загрузкой Excel/CSV по шаблону
   (опционально — «умный импорт» свободного текста). Валидация с понятными ошибками. Панель качества данных:
   введено пользователем / значение по умолчанию (с источником) / допущение.
2. **Процессы и подбор.** «Где деньги»: затраты по процессам (отбор 156 млн/год, перемещение паллет 47 млн/год…).
   Для каждого процесса: типы решений → продукты со статусом «подходит» / «требует проверки» / «исключён».
   У каждого статуса — причины. Скоринг раскладывается на вклады, веса можно менять. Можно вручную добавить продукт
   с предупреждением. Сравнение 2–4 продуктов бок о бок по 6 группам ТТХ с бейджами источника.
3. **Расчёт.** Конфигурация: время цикла → аналитическое N → проверка симуляцией → итоговое N с резервом.
   CAPEX и OPEX по статьям. Каждая строка раскрывается в формулу и источники. Сценарии «Как сейчас / Покупка / RaaS»
   (+ лизинг опционально) в одной таблице: годовой эффект, окупаемость простая и дисконтированная, NPV, ROI, TCO, денежный поток.
   Вывод — интерпретация по диапазонам (<3 / 3–5 / >5 лет) + риски, а не жёсткий порог.
4. **What-if и риски.** Слайдеры ключевых допущений с мгновенным пересчётом; торнадо-диаграмма чувствительности
   (≥3 параметров, в ТЗ минимум три); тепловая карта «ставка ФОТ × объём»; Монте-Карло по min/max датасета:
   «с вероятностью 80% окупится быстрее 3,1 года».
5. **Имитация.** 2D-карта объекта: зоны, маршруты, роботы, точки операций и зарядки. Старт / пауза / перезапуск,
   скорость, выбор сценария, режим «пиковый день», отказ робота. KPI в реальном времени: выполнено против спроса, очередь,
   SLA, загрузка, доля зарядки, тепловая карта заторов. Блок сверки: «расчёт 136 палл/ч — имитация 131 (−4%) ✓».
6. **Отчёт.** PDF «предТЭО»: параметры, решения, состав, экономика, формулы, источники, ограничения, дата, версия модели,
   пометка «предварительная оценка». Excel **с живыми формулами**, чтобы финансист мог проверить расчёт сам.
   PNG/GIF имитации. Опционально — запрос КП вендорам (RFQ).

**Каталог** (доступен гостю): иерархия отрасль → объект → процесс → тип → продукт; поиск, фильтры, сортировка, сравнение;
полнота карточки в %; бейджи «Есть в реестре 719», «Протестировано ФЦ БАС», «ТТХ подтверждены».

**Админка:** CRUD каталога, импорт CSV организатора, очередь обогащения ТТХ из открытых источников с модерацией,
реестр нормативов и допущений с версиями, справочники параметров объектов.

**Гость:** каталог + демо-проект склада с ограниченным what-if («подвигай зарплату — увидишь окупаемость») → регистрация.

## Функции по приоритету

**P0 — обязательное по ТЗ** (без этого не попасть в топ-10):
- роли гость / пользователь / админ, хэши паролей, изоляция проектов;
- проекты: создать, копировать, удалить, версии;
- 3 типа объектов на уровне параметров и доступных решений, склад — в полную глубину;
- формы, импорт по шаблону, валидация;
- каталог: CRUD, фильтры, сравнение, происхождение данных;
- подбор: жёсткие ограничения + объяснимый скоринг;
- экономика: все метрики, формулы в UI, 3 сценария, чувствительность ≥3;
- 2D-имитация с управлением, влияющая на расчёт;
- PDF + Excel; воспроизводимость расчёта (версия данных и модели);
- OpenAPI, docker compose, документация.

**P1 — отрыв от конкурентов:**
1. Производительность из времени цикла + симуляция уточняет N и резерв («паспорт против физики»).
2. Реестр допущений: у каждого числа есть бейдж источника, версии задаёт админ, счётчик «0 недокументированных коэффициентов».
3. Excel с живыми формулами.
4. Риск-профиль: торнадо + Монте-Карло P10/P50/P90 окупаемости.
5. Стресс-тест в имитации: пиковый день и отказ робота → обоснование резерва.
6. Обогащение ТТХ каталога из открытых источников + бейджи 719 и «Протестировано» + полнота карточки.
7. **Калибровка по методике ФЦ БАС:** модельный кейс из их PDF («складской AMR: 4,4 млн против 9,4 млн ₽ за 3 года»)
   воспроизводится нашим движком. Автотест фиксирует расхождение, а в UI висит бейдж «сверено с методикой ФЦ БАС».

**P2 — если останется время:**
- умный импорт (LLM) из текста или произвольного файла;
- финансирование: лизинг или кредит при ставке ЦБ 14% против льготных 1–5%;
- проверка применимости мер господдержки по ОКВЭД, локализации и доле российских роботов
  (кешбэк 20%, ФРП, налоговый коэффициент 2; большинство мер — только для ОКВЭД C);
- RaaS с оплатой за операцию и точкой безубыточности по загрузке;
- RFQ вендорам;
- what-if для гостя;
- аналитика спроса для ФЦ БАС;
- 3D-вид на тех же событиях.

## Модель расчёта (контур)

- **Спрос:** суточные объёмы по процессам → часовой профиль (допущение с источником) × пиковый коэффициент.
- **Производительность робота:** 3600 / (2L/v_эфф + t_захвата + t_отдачи + t_лифта) × доступность (цикл «работа / зарядка»)
  × загрузка (70–85% по легенде). L берётся из сгенерированной планировки.
- **Количество:** N₀ = ⌈пик / производительность⌉ → симуляция N₀−1…N₀+2 → минимальное N с SLA ≥ цели →
  резерв по результату стресс-теста (легенда: 15–20%).
- **База (как сейчас):** ФОТ по процессам × 12 × 1,302 + техника + потери; индексация.
- **Покупка:** CAPEX = цена с НДС × N + зарядки + инфраструктура (разметка, Wi-Fi) + ПО + интеграция (WMS/1С) + ПНР +
  обучение + резерв 10%. OPEX = сервис + лицензии + электроэнергия + связь + АКБ (замена раз в 3–5 лет) + персонал
  эксплуатации. Замены по сроку службы внутри горизонта.
- **RaaS:** абонентская плата за робота в месяц (бенчмарк рынка) + разовое подключение; сервис включён; срок договора и выкуп.
- **Эффект** = высвобождаемый ФОТ + иные измеримые эффекты − доп. OPEX.
- **Метрики:** окупаемость = CAPEX / эффект; ROI = (Σэффект − CAPEX) / CAPEX; NPV и дисконтированная окупаемость
  (ставка по умолчанию — ключевая ставка ЦБ 14% на 11.09.2026, настраивается); TCO за горизонт (склад 5, остальные 7 лет).
- **Значения по умолчанию** для того, чего нет в данных (интеграция 0,5–2 млн, зарядка 200–400 тыс., сервис ≈10%/год,
  RaaS от 100 тыс. ₽/мес за робота), берём из `docs/MARKET.md` со ссылками.

Все коэффициенты живут в реестре допущений. Подробная спецификация модели — отдельный документ, когда модель утвердим.

## Демо на 5–7 минут

1. **0:00 Крючок.** «Склад 20 000 м², 180 человек, текучесть, ФОТ 203 млн в год. Вендор обещает окупаемость за год. Проверим».
2. **0:40 Проект из датасета организатора.** Загрузили Excel → 2 предупреждения валидации, видно, где допущения.
3. **1:20 Подбор.** Из 187 продуктов 9 подходят, 4 требуют проверки, остальные исключены с причинами
   («подъём 1,6 м < верхнего яруса 8,4 м»). Раскладка скоринга.
4. **2:10 «Паспорт против физики».** Паспорт даёт 2 робота, цикл на нашей планировке — 11. Запускаем имитацию:
   при 11 в пик растёт очередь, SLA 91% → система берёт 12 + резерв. Отключаем робота — SLA держится.
5. **3:30 Экономика.** «Как сейчас / Покупка / RaaS»: окупаемость 2,6 против 1,9 года, NPV, формулы раскрываются, у каждого числа источник.
6. **4:30 Риски.** Торнадо: главный драйвер — ставка ФОТ. Монте-Карло: 82% вероятность окупиться быстрее 3 лет.
7. **5:15 Отчёт.** PDF + Excel с живыми формулами. Админ меняет цену в каталоге → пересчёт с новой версией.
8. **6:00 Масштаб.** Аэропорт и больница (параметры и решения), архитектура расширения, готовность к пилоту с ФЦ БАС.

Цифры в сценарии — иллюстрация, реальные даст модель.

## Чего не делаем

- CAD и редактор планировок: планировка генерируется из параметров, максимум — простая правка зон.
- Физика и точный path planning: граф маршрутов с пропускной способностью проходов — достаточно.
- Реальные интеграции с WMS/ERP/1С: описываем API и сценарии интеграции (ТЗ 3.8.3).
- Три объекта в одинаковой глубине (Q&A: глубина одного важнее).
- LLM в расчётах.
