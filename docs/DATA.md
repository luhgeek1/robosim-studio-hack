## Главное

- **Датасет объектов — по одному демо-объекту на тип** (склад, аэропорт, медучреждение). Это не выборка. Поля формулами
  не связаны; min/max — границы для валидации формы, а не сценарии.
- **Каталог: 223 строки = 187 уникальных продуктов**, 103 компании, все российские. PDF-каталог — те же 223 строки в картинках.
  **Структурированных ТТХ нет совсем** (грузоподъёмность, скорость, габариты и прочее — только в тексте у единиц).
  Их нужно обогащать самим, с источником и датой (ТЗ 3.3.4, Доп. 3.2).
- **Цены — только «железо», с НДС, округлённые** (85% кратны 100 тыс.). ПО, ПНР, сервиса, срока службы и RaaS в данных нет.
- **Для склада, аэропорта и больницы релевантны ~47 уникальных позиций**, остальное — дроны, агро, море, стройка, трубы.
- **Внутрибольничных роботов-доставщиков в каталоге нет.** Склад — самый обеспеченный данными объект.

## `Датасеты_хакатон.xlsx`

Листы: `Склад`, `Аэропорт`, `Медучреждение`, `Легенда и использование`.
Колонки: `Параметр | Ед. изм. | Базовое значение | Диапазон (min) | Диапазон (max) | Примечание / источник допущения`.

**Особенности парсинга:**
- строки-разделы «▌ …» объединены по A:F — их нужно пропускать и помнить текущий раздел;
- в C смешаны числа, строки («1200×800×1600» с символом ×, «24/7/365», «Да (ЕМИАС)», «Да » с пробелом) и формулы
  (`Аэропорт!C28 = C4*0.6`);
- проценты — целые (30 = 30%), у категориальных полей в min/max стоит «-».

**Легенда (нормативы организатора — можно ссылаться как на источник):**
- резерв к пиковой потребности 15–20%;
- загрузка AMR 70–85%;
- CAPEX = оборудование + ПО + интеграция + ПНР + обучение + резерв 10%;
- OPEX = сервис + лицензии + электроэнергия + расходники; замена АКБ раз в 3–5 лет;
- начисления на ФОТ 30,2%.

**Пиковая нагрузка:**
- паллеты: 2000 перемещений / 22 ч × 1,5 = **136 палл/ч**;
- отбор: 100 000 / 22 × 1,5 = **6818 строк/ч**, это ≈45 отборщиков одновременно.

**Ловушки:**
- в примечании «2 смены по 12 ч», а в значении 11 ч;
- нет зарплаты упаковщиков и ещё 35 человек из 180;
- нет числа ворот и доков, расстояний «приёмка → хранение → отгрузка», площади уборки;
- опечатка «еврооддон».

## `catalog_export_v4.csv`

**Формат:**
- разделитель `;`, UTF-8 с BOM, CRLF, многострочные поля в кавычках (282 физические строки → 223 записи);
- цена `"2 700 000,00"` (пробел и запятая), «Рын Потенциал» `4.00` (точка);
- колонки `тип` (brs 147 / bas 72 / software 4) и `Тип` (11 категорий, пусто в 67) различаются только регистром — конфликт в SQL.

**Поля:**
- `id` (UUID, 187 уникальных), `Название`, `статус` (operation 132 / piloting 63 / rnd 28), `компания` (103);
- `описание` (пусто в 115), `Подтип` (72 значения, пусто в 80), `Сценарий` (97 значений);
- `Кейсы` (100%), `УГТ` (3–9), `Рын Потенциал` (2–5), `Регион` (24, Москва 105), `Отрасль` (9);
- `Цена изделия` (0,4–120 млн, медиана 4,0).

**Дубли:**
- 23 id повторяются (36 лишних строк); внутри группы всегда различаются `Сценарий` и `Отрасль`;
- цена различается только в 3 группах;
- по Q&A не удалять, показывать как альтернативы; **для склада — строки с отраслью «Торговля и услуги»**.

**Качество:**
- разнобой подтипов («Робот-уборщик» / «Робот уборщик», «штабелер» / «штабелёр»);
- пробелы в конце, `\r\n` внутри значений, опечатки;
- статус противоречит УГТ у нескольких позиций;
- Ортез-1 помечен как дрон;
- неясно, за что цена у систем хранения (SmartCube 2,7 млн, AS-RS 10 млн, Pallet Shuttle 7 млн) — за единицу или за систему.

**Нужны нормализация и словарь синонимов.**

**Поля «страна» нет** (все позиции российские). «Тип объекта», ограничения и инфраструктура — 0%.

## Как связать объект с каталогом

Поля «тип объекта» в каталоге нет, нужен собственный справочник **процесс → тип решения → `Сценарий` / `Подтип` в CSV**.

| Объект | Процесс | Тип решения |
|---|---|---|
| Склад | перемещение паллет (приёмка, размещение, отгрузка) | AMR, FMR, тягачи |
| Склад | отбор строк | доставка товара к человеку (Ronavi M, SmartCube, AS-RS B), Pick by Voice / Pick by Light |
| Склад | высотное хранение | шаттл, AS-RS P |
| Склад | площадь | уборка |
| Аэропорт | багаж | тягачи (Cognitive Pilot — 45 шт. в Пулково), сортировщики |
| Аэропорт | тележки и мусор | AMR-буксиры, EVOCARGO |
| Аэропорт | 51 000 м² | уборка (MARK 2 SE — кейс Красноярского аэропорта) |
| Аэропорт | терминал | патруль, консультант (Promobot) |
| Больница | питание, бельё, отходы | AMR-буксир или робот под тележку ≥120 кг |
| Больница | медикаменты, пробы | малые доставщики (вне каталога) |
| Больница | площадь | уборка (Клинботикс 600 — кейс НИИ Склифосовского) |

**Жёсткие фильтры (кандидаты):**
- грузоподъёмность ≥ масса груза (800 / 18–35 / 120 / 55 кг);
- ширина робота + зазор ≤ проход (2,8 / 3,5 / 2,4 м);
- высота подъёма ≥ нужный ярус;
- рабочая температура (перрон до −25 °C);
- шум (30 / 70 дБА);
- ровность пола;
- суммарная мощность зарядки ≤ 500 / 300 / 80 кВт;
- CAPEX ≤ бюджета (80 / 120 / 35 млн);
- интеграция с лифтами и СКУД;
- статус (rnd — только с пометкой).

**Чего нет и что придётся допускать (в реестр допущений, с источником):**
- длины маршрутов (кроме 25 м на строку и 180 м в больнице);
- времена погрузки и выгрузки, цикл лифта, режим работы аэропорта;
- производительность, точность и срок службы большинства продуктов;
- стоимость ПО, сервиса, RaaS;
- доля высвобождаемого персонала по процессам.

## Результаты исследований (22.09)

**Сценарии ФЦ БАС** (`research/fcbas_scenarios/README.md`, `cards.json`, 16 PDF + текст) — калибровочные точки методики заказчика:
- склад: 1 робот = 1 линия отгрузки (pick-by-line, пробег 200 м) = 3 человека в 3 смены; робот 99 500 палл/год, люди 97 000;
  3 года — 4,4 млн ₽ с роботом против 9,4 млн с людьми (карточка: 3,5 млн в первый год + 0,3 млн/год);
  средняя цена робота (вывод) ≈ 2,97 млн ₽; потенциал 14 800 роботов ≈ 44 млрд ₽;
- уборка: кредит 21% / 16% / 5% аннуитетом на 36 мес; себестоимость 1,31 млн ₽/год с роботом против 1,94 млн с людьми;
- на сайте 58 карточек (16 БРС + 42 БАС) со структурой «отрасль, задача, заказчики, параметры, стоимость, эффекты,
  комплект, подходящие БРС, ПО, уровень внедрения, барьеры» — ориентир для нашей карточки сценария и отчёта.

**ТТХ роботов** (`research/catalog_specs/warehouse_specs.yaml`, 35 продуктов, 19 ключей): заполнено 34% ячеек
(147 подтверждённых вендором, 69 заявок, 12 выводов). Ловушки:
- никто не публикует шум, IP, срок службы и требования к полу — это будут допущения команды с пометкой;
- противоречия: Ronavi H1500 — скорость 1,5 (спецификация) против 1,3 м/с (кейс), автономность 10 ч против 6 ч
  (организатор) против 3–5 ч (обзор); МОРОС AMR 100 — 150 кг / 3 м/с против 90 кг / 0,8 м/с;
- цены каталога против вендорских: Ronavi SD в каталоге 1,40 млн, у вендора 0,36–0,40; H2000 в каталоге 2,64 —
  ниже вендорского минимума 2,805; Pallet Shuttle 7,0 млн против ≈28 тыс. € за шаттл;
- аренда: единственная опубликованная ставка — R2B Mark 2 SE от 100 тыс. ₽/мес; Ronavi — три модели оплаты без цен;
- реестр Минпромторга явно заявлен только у ДиКом;
- не закрыто: Клинботикс 600, АК-SC80, роботы Яндекса (SPA-сайт), Сбер, Сёмабот, SmartCube, MULE, МФТИ.

При загрузке в каталог: значение с `status: confirmed` → `confirmed`, `claim` → `vendor_claim`, `inferred` → `assumption`;
противоречия показываем как два значения с источниками, в расчёт берём консервативное.

  40, аэропорту 13, больнице 10. Внутрибольничных доставщиков нет — 4 AMR с тележками помечены «лифты и двери
  не подтверждены».
- **ТТХ из research:** у тягачей буксируемая масса лежит в `payload_kg`, у EVOCARGO запас хода — в `runtime_h`,
  высоты систем хранения и мачт сканирования — в `lift_height_mm`; загрузчик переносит их в `towing_capacity_kg`,
  `range_km`, `max_storage_height_m`, `max_scan_height_m` по тексту единицы. Габариты и температура раскладываются на
  числа (`width_mm`, `operating_temp_min_c` и т.д.) для жёстких проверок.
- **Нормативы v1:** 115 значений, 29 источников (с 23.09 — 20 нормативов планировки). Подтверждены 22.09: НДС 22%
  (425-ФЗ), ключевая ставка 14% (ЦБ, 11.09.2026),
  налог на прибыль 25%, ставки кредитов МСП 15,1%, тариф Мосэнергосбыта 2026. 62 значения — допущения команды
  (источник `team`, у каждого обоснование); сильнее всего на результат влияют `labor_release_share_*`,
  `effective_speed_factor`, `g2p_robot_lines_per_trip`, `discount_rate`, `commissioning_share_of_hardware`.
- **Трактовка загрузки:** `amr_utilization_target` (0,8) — доля *доступного* времени; зарядка учитывается отдельно
  (`analytic_availability_default` 0,75 или по ТТХ, затем симуляция). Произведение строже легенды (0,6) — осознанно
  консервативно; при реализации ядра проверить на калибровке ФЦ БАС.

## Экономика и калибровка (22.09)

**Калибровка по ФЦ БАС** (`backend/app/seeds/data/calibration.yaml`, пересчитывается при каждом расчёте):
- аннуитет кредита 2,2 млн ₽ под 21 % на 36 мес.: у нас 994,6 тыс. ₽ в год, у ФЦ БАС 995 — формула совпадает;
- «1 робот = 3 человека», 3 года: стоимость людей у нас 9,40 млн ₽ против 9,4; роботизированная линия — 6,64 млн ₽
  против 4,4 (+51 %). В модельном кейсе ФЦ БАС нет ПНР (0,33 млн), резерва CAPEX (0,38), лицензий и подписки ПО
  (0,33) и персонала эксплуатации (0,7). Вывод «робот дешевле трёх человек» сохраняется: 6,6 против 9,4 млн;
- производительность робота: ФЦ БАС закладывает 99 500 палл/год (11,4 палл/ч круглосуточно, идеальный цикл),
  у нас — 33 000 по их же паспорту H1500 (1,3 м/с, 240 мин работы на 80 мин зарядки) с эффективной скоростью
  и загрузкой парка. Итоговое N проверит имитация.

**Датасет: численность не связана с объёмами.** Так в больнице 18 сотрудников «транспорта белья» возят 65 контейнеров
в сутки, а 2/3 персонала терминала (120 человек) — 505 рейсов тележек. Поэтому высвобождение ограничено потолком:
человеко-часы самого объёма работ вручную, D-015. Пересмотрены доли в справочнике (обоснование — в карточке процесса):
- аэропорт: тележки и мусор — 0,12 персонала терминала (≈ 22 человека по объёму рейсов), уборка — 0,1
  (в терминале 8 поломоечных машин, база — машинная уборка 1000 м²/ч); багаж — тягач заменяет только водителя
  (`tow_driving_share` 0,3);
- больница: раздатчики питания замещаются «только в транспортной функции» (датасет) — `meal_transport_share` 0,4;
  спрос на питание, бельё, отходы и пробы переведён в рейсы через загрузку за рейс (порции отделения, контейнер 55 кг,
  вывоз с точки, обход лаборатории).

**Демо-объекты (расчёт «из подбора», покупка):** больница — уборка роботами окупается за 3,3 года, аэропорт — уборка
терминала за 3,5 года; доставка в больнице и багажные тягачи при таких объёмах не окупаются. Склад с маршрутом 200 м
из модельного кейса ФЦ БАС не окупался ни на паллетах (18 лет), ни на G2P — см. «Планировка склада».

## Планировка склада (23.09)

Генератор строит схему по параметрам объекта и 20 нормативам категории `layout` (D-017). Геометрия стеллажей опирается
на EN 15620 (зазоры 75 мм → секция 2,8 м на 3 европаллеты, зазор спаренных рядов 0,2 м, шаг яруса 1,9 м), зазор до
оросителей — на NFPA 13 (0,5 м), зона «товар к человеку» — на модели RMFS (Lamballais, Roy, De Koster, 2017).
Остальные 12 — допущения команды: пропорции здания 2 : 1, глубина зоны у ворот 15 м, 30 паллет/ч на ворота и т.д.

**Демо-склад** (20 000 м², потолок 10 м, 20 000 паллетомест, 2 × 11 ч):
- здание 200 × 100 м, 5 ярусов, 1 поперечный проезд, 25 рабочих проходов по 780 паллетомест. Вмещается 19 500
  из 20 000 паллетомест, и генератор об этом предупреждает: справа нужно место под 23 станции G2P
  (6 818 строк/ч в пик / 300 строк/ч на станцию);
- ворота 3 + 3 (68 палл/ч в пик / 30), 8 мест зарядки, 1 710 мобильных стеллажей G2P, 1 181 узел и 1 421 ребро;
- средние маршруты по графу: ворота приёмки → ячейка 91 м, ячейка → ворота отгрузки 98 м, стеллаж G2P → станция
  42,5 м (норматив был 40 м — совпадает), ячейка → зарядка 78 м. Генерация и маршруты занимают около 20 мс.

**Что изменилось в экономике** (паллеты, покупка, 5 лет, ставка 18 %). Маршрут 94,7 м вместо норматива 200 м:
- H1500: 17 роботов, окупаемость 4,8 года (было 18), IRR 7,6 %, NPV −15 млн. Потолок высвобождения тоже падает
  (человек не быстрее робота на том же маршруте), поэтому эффект меньше, чем даёт один короткий цикл.
- Рекомендация «из подбора»: AMR 800 (17 шт.), окупаемость 3,0 года, NPV +10,7 млн, IRR 27,5 %, вердикт «обоснованно».
  RaaS того же парка — 5,8 года и NPV −2,2 млн.

Ограничения: хранение случайное (все ячейки равновероятны), классы ABC не учитываются. Это консервативно: при хранении
по оборачиваемости маршрут короче.

## Имитация на демо-складе (23.09)

Сценарий «из подбора»: AMR 800 на перемещение паллет, 2 000 палл/сут, пик 136 палл/ч, SLA — 95 % паллет за 20 минут.
- Пиковый режим (4 ч + 30 мин разогрева): при 14 роботах по циклу SLA 100 %, но загрузка парка только 48 %.
  Перебор флота (5 повторов на каждое N, общие случайные числа): 7 роботов — 58 %, 8 — 95,7 %, 9 — 100 %.
  Итог — 9 + 2 резерва вместо 14 + 3 (с 29.09 парк принят, только если SLA держат все прогоны, D-029; при 8 роботах
  худший из 5 прогонов — 87 %). CAPEX 35,2 млн вместо 50,2, окупаемость 1,9 года вместо 3,0, NPV +33 млн вместо +10,7.
  Перебор занимает 1,7 с, прогон пикового режима — 0,2–0,4 с, обычный день с отказом робота — 0,4 с.
- **Почему меньше, чем по циклу.** Формула считает пробег «2 × средний маршрут». В имитации ближайший свободный
  робот берёт следующую задачу рядом с местом, где закончил, и пустой пробег короче. Модель ограничений
  при этом тоже учитывается: заторы в однополосных проходах, очередь у ворот, зарядки, отказы.
- **G2P** (100 000 строк/сут): при исходных формулах 138 роботов и 23 станции давали SLA 11 %. Робот стоит
  у станции, пока отбирают его строки (36 с на рейс), а станции были загружены на 99 %. Поэтому в цикл G2P
  добавлена стоянка у станции, а станции считаются с целевой загрузкой 0,85 (`g2p_station_utilization_target`,
  M/M/1). Сейчас 27 станций в два ряда, по циклу 155 роботов, по имитации 205, узкое место — станции (79 %).
  Отбор на G2P не окупается.

## Заметки организатора о влиянии полей (24.09)

Последний столбец листов датасета — комментарий организатора, как поле должно влиять. По ним сделаны правила D-026:
«Наличие WMS обязательно для роботизации», «Обеззараживание … учитывается в OPEX», «Н≥5 этажей = обязательные
лифты», «без API лифтов AMR не может самостоятельно переходить между этажами», «не все роботы допущены на
перрон», «ровность пола критична для AutoStore и высотных решений», мощность — «для зарядных станций роботов».

Несогласованности, которые ловят проверки (данные демонстрационные, Q&A 16.09):
- склад: 150 строк/ч × 25 м на строку = 3 750 м ходьбы в час — больше, чем проходит человек с тележкой;
  проверка `picker_route_is_walkable` — информационная;
- больница: порции питания против коек (было и раньше).

Пробел данных: массы грузовой тележки и контейнера мусора в терминале нет — допущение
`airport_terminal_cart_weight_kg` = 250 кг; без него тягачи для этого процесса не считались вовсе.
